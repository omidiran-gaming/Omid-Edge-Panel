🔐 What Is ECH?

ECH (Encrypted Client Hello) is a TLS feature designed to encrypt domain information that would otherwise be exposed in plain text。

For a more detailed technical explanation, see Cloudflare’s official blog:
👉 https://blog.cloudflare.com/zh-cn/announcing-encrypted-client-hello/

📖 Background

When we use WS + TLS nodes for proxying:

  • ✅ The actual traffic is encrypted by TLS, so the GFW cannot see the specific content you access
  • ❌ However, an important piece of information is still exposed during the TLS handshake:SNI

SNI is the node’s camouflage domain (HOST)

In other words:

The GFW may not know what you are accessing, but it can tell that you are using a proxy and which domain you connect to.

⚠️ What problems can this cause?

This is why issues often occur in the following scenarios:

  • ❌ Batch real-link latency tests in v2rayN
  • ❌ Automatic node selection in Clash policy groups

Typical symptoms:

All nodes suddenly show -1 and become unusable

The nodes may not actually be offline; instead, the ISP/GFW may disrupt proxy connections by blocking the node domain。
Because this blocking is often automated and prone to false positives, the node may work again after some time, then the cycle repeats.

💡 What ECH Does

The main purpose of ECH is to:

Encrypt the SNI (the node domain)

When ECH is enabled:

  • ✅ GFW The real node domain cannot be read
  • ✅ External observers will see the following domain instead:cloudflare-ech.com

This prevents, at the source, precise node blocking based on the domain。

🤔 Can ECH Be Blocked?

In theory, the GFW only needs to block cloudflare-ech.com to do so.

But doing so would:

  • ❌ Affect many legitimate websites and services that use ECH
  • ❌ Create higher blocking costs and side effects

Therefore,how long ECH remains useful depends on the GFW’s choices and policies; for now, it remains quite effective.

🔍 How to Verify ECH

You can use a simple, straightforward method to verify that ECH is working.

📋 Verification Steps

  1. Open the node’s 「⚙️ Detailed Configuration」
  2. In HOST enter manually a domain used by your project that is currently blocked, for example: *.workers.dev
  3. After saving the settings, update the subscription again
  4. Find the following in the node list:
    • - A node whose HOST is *.workers.dev
    • - Then try connecting to that node

✅ Interpreting the Result

  • ✅ If the node connects and works normally
    This means ECH is working; the blocked domain is hidden and only the following is visible externally: cloudflare-ech.com
  • ❌ If the node cannot connect
    ECH may not be working, or the client version/DNS configuration may be incorrect.

⚠️ Disable TLS Transport Encryption

🔒 You are about to disable Shadowsocks TLS transport encryption. To avoid losing connectivity, confirm that your deployment environment meets the requirements first.

☁️ Before disabling TLS, confirm these three points:
  1. The project must be deployed on Workers(not Pages).
  2. Disable “Always Use HTTPS”
    SSL/TLS > Edge Certificates > Always Use HTTPS > Off
    or HOST Use directly *.workers.dev the domain assigned to your project.
  3. The port used by the preferred IP/domain must be a HTTP port of this type, for example: 80、8080、8880、2052、2082、2086、2095。

📘 Transport and Encryption

📡 Without TLS, data is transmitted in plaintext over HTTP and no longer receives TLS transport encryption or camouflage.

🔐 The node is still encrypted by Shadowsocks AEAD (aes-128-gcm / aes-256-gcm); the traffic payload remains encrypted.

✅ Summary: the final traffic is transmitted as plaintext transport encrypted data。
